# 选项机制（choice-system）

## 选项格式

每个决策点呈现：

- **3 个 Agent 生成的选项**（A/B/C）
- **1 个自由输入**（"或者你自己输入……"）

选项必须**具体、可执行、贴合当下场景**，不能抽象（不能说"去社交"，要说"走过去和那个穿格子衬衫的同学搭话"）。

## 决策点频率

- 平淡日子：1-2 个决策点
- 重大日子（约会 / 面试 / 吵架 / 旅行）：4-6 个决策点
- **每天至少 1 个必选决策**：通常为早起穿搭；但可偶尔轮换为其他生活必选（午饭吃什么、要不要回这条消息、下雨带不带伞），避免每天重复穿搭选项产生机械感。穿搭仍是默认，只在内容上轮换，不每次硬凑

## 穿搭 → 影响事件（核心机制）

Agent 生成穿搭选项时，**内部**标注两个属性（不向用户明示）：

- 醒目度：低调 / 普通 / 惹眼
- 场合适配：是否适合今天的场合

影响规则：

- 惹眼的穿着 → 提高陌生人注意概率 → 触发搭讪、被夸赞、被盯着看等事件
- 低调的穿着 → 降低注意，但可能错过机会
- 场合适配错误 → 影响当天社交 / 活动效果

## 选项出现流程

1. 决策点出现前，Agent 用**两三句第三人称**交代当前场景（让选择有依据）
2. 用户选择后，Agent 给出**简短因果反馈**，然后推进到下一个场景
3. 场景之间用简要叙述连接，不把完整的"极致真实"正文提前展开（正文在提交后润色生成）

## 大小事判定

事件落地后，Agent 内部判断：

- **小事**：只叙述，不影响后续（被夸了一句、路上看到什么）
- **大事**：必须写进角色状态新版本（关系建立 / 破裂、金钱变动、健康变化、重大际遇）

判定标准：**会不会改变主角或其他角色的处境、关系或状态。** 会 → 大事；不会 → 小事。

## 提交确认

当天决策点走完后：

1. Agent 简要汇总今天走过的路（发生了哪些选择、哪些结果）
2. 询问："今天的故事要提交吗？"
3. 用户可确认提交，或补充 / 修改内容
4. 确认后 → 进入润色成文阶段

## 自动模式（挂机）

用户输入"今天全自动 / 自动模式"时：

- 跳过逐项决策：Agent 用看不见的骰子替主角做出当天全部决策（含穿搭、事件应对）
- 决策依据与用户选择同一套逻辑：角色性格、状态、关系累积、世界规则
- 提交前给用户**当天预览**：简述发生了哪些选择与结果
- 用户确认后照常润色成文、归档
- 自动模式不影响因果累积与一致性，所有结果照常入档

## 润色成文

提交后，Agent 把全天所有选择连贯成完整叙事：

- 填补决策之间没写到的空白（吃饭、通勤、上厕所、发呆）
- 保证因果连贯，选择的结果被如实呈现
- 以"极致真实"的白描写出完整的一天
- **标题 = 日期 + 当天一句话摘要**：润色时提炼 4-12 字的简要（如"搬家到新公寓""平凡的周五，加班到九点"），平淡日子也如实提炼，不硬凑戏剧性
- 完整正文写入 `正文/<YYYY-MM>/<YYYY-MM-DD> <简要>.md`：按月分子目录（Agent 按需创建当月目录），供用户查看、续写时读细节
- 同时在 `timeline/<日期>.md` 写入当天事实摘要（发生了什么、因果要点），供快速读档与一致性校验

## 看不见的骰子

- Agent 不显式掷骰，不展示概率数字
- 事件是否发生 = 性格 × 场合 × 状态 × 关系累积 × 随机
- 例：主角心情低落时遇到搭讪，可能更警惕；好感高的朋友更可能来邀请
- 随机性要带来真实的不确定性，但必须与累积状态一致
