# 事件池（event-pool）

"看不见的骰子"的选材库。每个场景，Agent 从下面的类型池抽取事件原型，再结合性格、状态、关系累积做概率修正。保证多样性，避免重复套路。

## 使用方式

- 从类型池中选择符合当天情境的事件原型，再叠加概率修正落地
- 普通日子倾向低烈度；重大日子才引入高烈度
- **新鲜度控制**：近期用过的类型降低再次抽取的概率，同一类事件不连天出现
- **每天至少抽 1 个落进当天**（主动事件节拍，见 choice-system），不让日子平铺

## 日常 / 通勤（低烈度，占大头）

- 差点赶不上车、忘带东西折返
- 路上遇到认识的人寒暄几句
- 被陌生人问路 / 递传单 / 推销
- 天气突然变化（被淋、暴晒、风把伞吹翻）
- 目睹一件小事（吵架、扶老人、小狗乱跑、外卖被偷）

## 社交 / 关系（中烈度）

- 被搭讪、被夸赞、被冷落
- 朋友约饭 / 借钱 / 求助
- 收到很久没联系的人的突然消息
- 撞见熟人、被拉去聚会
- 小圈子里的流言传到主角耳朵里

## 冲突 / 摩擦（中高烈度）

- 被误会、被冤枉、话说重了
- 排队 / 占座 / 插队的小纠纷
- 与同事、家人意见不合
- 一句玩笑伤了人，对方没接茬

## 机会 / 际遇（中烈度，稀缺）

- 兼职 / 实习 / 面试的机会
- 意外的邀请或推荐
- 进入一个新圈子（社团、饭局、爱好群）

## 意外 / 插曲（高烈度，低概率）

- 突发消息（坏消息或好消息）
- 身体突发状况（发烧、扭伤、胃疼）
- 财物出问题（手机摔了、钥匙丢了、钱被偷）
- 公共事件的波及（停电、封路、临时通知）

## 概率与克制

- 低烈度占大头，高烈度是稀缺调味，不天天洒
- 事件必须与主角处境自洽，不凭空安插
- 抽取后照常走"大小事判定"决定是否入档
- 插曲（高烈度）也受 `choice-system.md` 的插曲机制调度
