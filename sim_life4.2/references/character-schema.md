# 人物档案模板（character-schema）

每个角色一个文件：`sim-life-data/<人生名>/characters/<角色名>.md`

## 版本化规则

- 档案**按版本追加**，不覆盖历史
- 最新版本放在最上面，历史版本倒序向下排列
- 每次角色状态发生变化时追加一个新版本
- 新版本包含两部分：**本次变化**（和上一版的差异）+ **最新状态快照**（完整，供 Agent 直接读取）
- **版本封档**：版本累计较多（如超过 10 版或跨月）时，把旧版本压缩为一个"历史摘要"区（保留关键变化与转折），文件保持精简；读档仍读最新版 + 历史摘要
- **勘误**：用户纠正已记录的事实时，不改写旧版本——在档案顶部追加"勘误"版本（注明原记录、更正为、原因），正文文件末尾追加"勘误"说明块

## 档案格式

```
# <角色名>

## v<N> · <YYYY-MM-DD>（最新版，放最上面）

### 本次变化
- 与 v<N-1> 相比：<变化了什么>

### 最新状态
- 姓名：
- 性别：
- 外貌：身高 / 体型 / 面容 / 肤色 / 发型 / 衣着风格
- 年龄：<岁>（<出生日期>）
- 人生阶段：<学生 / 在职 / 失业 / 退休 / 其他——决定日常模板，见 life-stage.md>
- 家庭背景：
- 性格：
- 说话方式：<口头禅 / 句式 / 语速 / 爱用的语气词>
- 兴趣 / 技能：（每项附水平：入门 / 熟练 / 精通 / 资深；正在进行的项目）
- 健康：
- 经济：
- 职业 / 学业：
- 习惯 / 怪癖：（可选）
- 人生目标 / 执念：（可选）
- 心情：<近期情绪状态>
- 关键关系：（简列，详见 relations.md）
- 近期大事：

## v<N-1> · <YYYY-MM-DD>
（历史版本，保留）

...

## v1 · <YYYY-MM-DD>（初始档案）

### 初始设定
（首次捏人时填写，字段同上）
```

## 使用约定

- **Agent 读档**：读最上面的最新版本即可获得完整状态
- **Agent 写档**：有状态变化时在文件顶部追加 `## v<N+1>` 块，旧版本一律不动
- **新人物登场**：当故事中出现有名有姓、可能再次出现的新角色时，为其创建独立档案
- **路人**：一次性角色（地铁上的乘客、路过的店员）不建档案，只出现在 timeline 里
- **无变化不建版**：纯粹的日子过去、没有任何状态变化时，不新建版本
- **离线近况**：主角一段时间未接触某角色时，可依据该角色性格与处境补充其"离线近况"（合理推演，不凭空戏剧化），作为新版本或在 relations.md 里程碑中记录
- **NPC 生活状态机**：每个角色有简单生活状态（工作/恋爱/搬家/生病/缺钱/备考…），主角不在场时按性格与处境合理推进；再见时状态已变（"阿坤上个月进城了"），并可反向牵动主角（朋友搬家需要帮忙）
- **出现节拍**：常驻 NPC 几天内应被主角见到或被提起；超过约 7 天没出现，Agent 必须让 TA 浮现一次——主动找你、别人提起、或你偶遇。角色不会无声消失，要么回来，要么有交代
- **自主事件**：隔几天给 NPC 推进一个生活变化（搬家 / 换工作 / 恋爱 / 惹麻烦），不围绕主角，但会波及主角
- **NPC 的执念**：常驻 NPC 应有自己的小目标 / 执念（想升职、想追谁、想开自己的店）——与主角或其他 NPC 的目标冲突时，张力就来了（见 relations-schema 的张力）
- **能力成长**：长期重复的活动缓慢改变能力（坚持跑步 → 耐力见长），有实质进步时在新版本中更新对应兴趣/技能的水平
- **年龄推进**：跨过生日时在新版本更新年龄，并如实调整外貌、健康、体力的描述（见 life-stage.md 的时间跨度过长）
- **人物随时间演化**：性格、爱好、体质、口吻都会随经历改变——在最新状态的字段旁用（）标注变化日期与触发事件（例：性格：沉默寡言（08-12 被裁员后变得焦躁）；爱好：晨跑（09-01 体检后开始））。无变化的字段不标；字段变化即新版本
